# React frontend migration

## Boundaries

Streamlit remains runnable while the React application is introduced. The graph's nodes, conditional routing, Groq binding, tools, validation and deterministic report rendering are unchanged. FastAPI delegates chat to a private compiled copy of the existing builder per Live conversation. Structured market/news/list controls invoke the original tools with validated parameters and use the existing report renderer. Comparison calls the existing per-coin data tool for each requested asset; there was no independent comparison tool to replace. These tool-backed turns are added to the same graph checkpoint with `update_state`, so subsequent agent follow-ups retain their context without an extra model call for the structured action.

## Local API

All session routes require `X-Workspace-ID`, a UUID generated by the browser and held in session storage. Session IDs are separate random UUIDs. Requests cannot change an existing session's mode or retrieve another workspace's conversations. This is a local capability identifier, not an authenticated account system.

| Method | Route | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Readiness, no provider calls |
| GET | `/api/demo/preview` | Clearly fictional fixtures, without creating chat turns |
| POST | `/api/sessions` | Create `{mode: "demo" \| "live"}` |
| GET | `/api/sessions` | List this workspace's sessions |
| GET | `/api/sessions/{id}` | Restore turns, latest evidence and busy state |
| POST | `/api/sessions/{id}/chat` | `{message}` |
| POST | `/api/sessions/{id}/market` | `{symbols: ["BTC"]}` |
| POST | `/api/sessions/{id}/compare` | `{symbols: ["BTC", "ETH"]}` |
| POST | `/api/sessions/{id}/news` | `{query, max_items}` |
| POST | `/api/sessions/{id}/assets` | Ask the agent for supported coin symbols |
| GET | `/api/sessions/{id}/reports/{turn}` | Existing report text as a Markdown download |

Research responses contain the session's `turns` and a `latest` projection with `snapshots`, `articles`, `coins` and raw `evidence`. Each turn retains its own query, exact final reply, tool arguments/results and elapsed time. Model reasoning and API keys are not serialized.

Synchronous route functions run outside the ASGI event loop. A per-session lock returns HTTP 409 for overlapping research requests; separate sessions can run independently. HTTP 502 indicates a failed invocation and includes `context_reset: true` after discarding the incomplete checkpoint. Provider-level errors returned by tools remain inspectable evidence. HTTP 404 covers missing/expired sessions and reports; HTTP 422 covers invalid input.

Sessions expire after four idle hours. Capacity is 100 sessions per process and 100 turns per conversation. Demo is restricted to BTC/ETH structured market requests and uses the original scripted news scenarios. Live never uses fixtures. Browser request cancellation does not cancel an already-running graph: retrieve session state before retrying.

## Frontend design

The reference images informed the compact sidebar, slim market cards and dominant analyst conversation. The supporting panel has News and Comparison tabs; raw evidence uses per-response disclosure. Five sidebar destinations reveal focused views instead of showing all features at once.

CSS design tokens define complete light/dark palettes. Tailwind supplies layout and spacing utilities, Lucide supplies icons, and React renders all controls. There are no embedded Streamlit elements, external font dependencies, pretend notification controls, fabricated sparklines, sentiment badges or unsupported metrics. Exact source price strings retain decimal precision. Any rounded percentage is marked approximate. Source dates remain visible with their reported metadata.

At narrower widths the supporting panel stacks below chat. Below 760 px, navigation becomes a dismissible drawer with keyboard focus handling. The composer supports Enter, Shift+Enter and a labelled send control. Reduced-motion preferences disable animations. Markdown is rendered without raw HTML, source links allow HTTP(S) only, and remote report images are not loaded.

## Verification

Python HTTP tests cover CORS, workspace isolation, input validation, current-turn data, memory, reports, concurrent-session exclusion and safe failures. Existing Python and Streamlit regressions remain in the test suite. React tests cover requests, loading states, themes, mode isolation, comparisons, news, exports, session restoration and failure recovery. `frontend/scripts/smoke.mjs` checks real HTTP communication through Vite's proxy using Demo data.

Browser visual checks and any Live smoke results should be reported separately from unit tests. A passing mocked UI test does not certify provider availability or arbitrary model tool choices.

Migration verification completed:

- 66 Python tests, including the retained Streamlit regressions and 15 HTTP/API tests.
- 20 frontend tests for interactions, the HTTP client, keyboard tab navigation and light/dark text contrast.
- TypeScript checking and a successful Vite production build (approximately 132 kB gzipped JavaScript).
- Real Vite-to-FastAPI HTTP smoke checks for Demo memory, market data, comparisons, Markdown exports and CORS.
- Bounded Live requests returned BTC and ETH snapshots from FreeCryptoAPI and articles from NewsAPI. The finalized structured news route returned three requested articles, and a subsequent real Groq follow-up correctly remembered Ethereum.

The embedded browser timed out before opening the React preview. Final screenshot-based desktop/mobile layout checks remain unverified. Theme behavior and mobile-navigation interactions have automated coverage; the responsive CSS breakpoints still require visual inspection.
